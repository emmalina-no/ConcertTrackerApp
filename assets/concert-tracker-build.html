01 Foundation

One codebase, three stages

The app is a single Expo project that ships to iOS, Android and the web from the same TypeScript source. expo-router turns the file tree under src/app directly into the navigation tree — a screen is a file, not a route config.

src/app/(tabs)Concerts · Stats · Library
＋
src/app/*event, artist, venue stack screens
→
expo-routerfile → route

Where a screen needs different DOM behaviour, a .web.tsx sibling file wins on web while the default file keeps serving native — used for the date picker (see track 07).

02 Data & backend

Supabase behind one gateway

There's no custom server. Supabase supplies Postgres, auth and row-level access straight from the client. Every query the app makes goes through a single file — src/lib/api.ts — so screens never talk to Supabase directly.

Schema, in four tables

eventsname, dates, notes
venuesname, city, country
⋈
event_artistsjoin · played_date
artistsname

Creating a concert looks up or inserts its venue and artists on the fly (findOrCreateVenue, findOrCreateArtist), then rewrites the event_artists lineup for that event.

03 Session

Auth guards the whole tree

AuthProvider wraps the app in a context that mirrors Supabase's session — persisted to AsyncStorage so a refresh doesn't sign you out. The root layout reads it once and splits the entire route tree with Stack.Protected.

Root layout, in effect

  • Signed in → tabs, event / artist / venue screens
  • Signed out → login only
04 Navigation

Tabs for browsing, a stack for detail

Three tabs cover the everyday views; drilling into a concert, artist or venue pushes a stack screen on top, each with its own header.

ScreenFileRole
Concerts(tabs)/index.tsxPast & upcoming list, filters
Stats(tabs)/stats.tsxPer-year chart, top artists, countries

Concert detailevent/[id].tsxEdit / delete a logged show

Refreshing a detail screen (or opening it from a link) leaves no history to go "back" to — a custom HeaderBackButton checks router.canGoBack() and falls back to Library or Concerts instead of vanishing.

05 Design system

Themed primitives, not scattered colors

A single palette in constants/theme.ts defines light and dark values for text, backgrounds and three accent colors. useTheme() reads the device scheme and hands components their colors — the same tokens power this page.

ThemedView / ThemedText

Drop-in View / Text replacements that pull background and color straight from the active theme.

Navigation chrome

Header background, tint and border are mapped from the same palette, so stack headers match the app instead of React Navigation's defaults.

06 Insights

Stats computed on the device

getStats() pulls every past concert once and reduces it client-side — no aggregate SQL — into per-year counts, a ranked artist list and a set of countries visited, which the Stats tab renders as a bar chart, a top-5 list and pills.

07 Platform seams

Where native and web diverge

Most of the app is one implementation for every platform. Dates are the exception: native uses @react-native-community/datetimepicker, while date-field.web.tsx drives a real <input type="date"> under a theme-matched overlay, so it opens on click and always reads dd/mm/yyyy regardless of browser locale.
